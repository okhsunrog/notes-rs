# Рукописные заметки: передача бэкенда фронтенду

Дата: 2026-09-06. Ветка: `handwriting-prototype`.
Репозиторий: `/home/okhsunrog/code/rust/notes-rs`.

Бэкенд рукописи переведён на обычные заметки, общую `notes.db` и синхронизацию
через `notes-server`. Интерфейс намеренно не адаптирован: это следующий этап.
Этот документ заменяет описание текущих границ в старом журнале прототипа.

## Что реализовано

- `PageKind::Handwriting`, в TypeScript `page.kind.kind === "handwriting"`.
  Заметка имеет обычный UUID, заголовок, находится в общем списке, удаляется через
  существующий механизм заметок. У неё нет текстового блока-заглушки.
  Тип содержимого неизменяемый; текстовые блоки и изменение текстового layout
  для рукописи отклоняются ядром.
- Миграция V004 общей `notes.db`. Авторитетные данные на клиенте — SQLite BLOB:
  CBOR-записи в `ink_records`, колоночная геометрия INKCHNK/PCO-8 в `ink_chunks`.
  `ink_documents` содержит рабочую версию каждой заметки; `ink_history` — её историю.
  Это не одна большая запись со всей заметкой. `ink-format` остаётся независимым
  крейтом без зависимости от приложения, SQLite и сети.
- Отдельный Rust-адаптер `handwriting/ink-v1.sqlite3` и команды singleton-черновика
  удалены. Миграции тестовых черновиков нет по решению пользователя. Старый файл
  на книге не удалялся: установленная старая сборка пока продолжает использовать его.
  Названия DTO `InkDraft*` пока сохранены: это модель данных страницы для IPC,
  а не отдельная сущность черновика или формат хранения на диске.
- У каждого документа собственная очередь записи. Завершённый жест записывает
  только изменённые штрихи и метаданные в транзакции SQLite с `synchronous=FULL`.
  Команда возвращает новую revision только после commit. Другие заметки не
  используют общую блокировку ввода; запись SQLite физически по-прежнему имеет
  одного писателя.
- Постоянные Undo/Redo на 50 действий на заметку. Возвращаются дельты истории,
  а не все точки страницы. Revision — уникальный токен перехода, защищающий от
  запоздалых записей и ABA после Undo/Redo. Компакция revision не меняет.
- Минутная компакция и завершение сессии используют одну последовательную очередь.
  Завершение сначала сохраняет намерение публикации в БД. Ошибка компакции не
  публикует неполную версию; повтор и перезапуск сохраняют локальные данные.
- Публикация неизменяемого корня и запись `InkPublish` в существующий sync outbox
  выполняются атомарно. Есть восстановление незавершённых сессий при запуске.
- `notes-sync` и `notes-server`: аутентифицированные бинарные пакеты недостающих
  блоков, проверка хешей, принадлежности пользователю, квоты, полноты графа и
  поддерживаемого содержимого. HTTP и WebSocket отклоняют публикацию без всех блоков.
- Causal DAG опубликованных версий. Конкурентные ветки сохраняются без LWW для
  рисунка. API позволяет оставить выбранную ветку либо несколько веток отдельными
  заметками. Запоздалый ответ старого диалога конфликтов отклоняется.
- Существующий архив рабочей области `.notes` включает бинарную рукопись, текущие
  неопубликованные изменения и все конфликтующие варианты. Manifest v8, бинарный
  контейнер v1. Архивы v7 с текстом читаются; архив с рукописными identity без данных
  не считается успешной копией. Восстановление, новые версии и outbox атомарны.
  Локальная Undo-история в архив не входит, как и глобальная история текстовых правок.

## Когда происходят запись, сжатие и сеть

| Событие                                                            | Действие                                                                                                                                                             |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Завершился штрих, стирание, перемещение или смена фона             | Сериализованная локальная запись жеста и истории. Новая геометрия сразу PCO-8. Публикации рисунка в сеть нет.                                                        |
| Прошла минута при наличии новых блоков или незавершённой компакции | Один ограниченный проход объединения. Продолжающееся письмо не отодвигает срок. Сеть не запускается.                                                                 |
| Выход из заметки, уход в фон                                       | Сначала фронтенд заканчивает жест и сбрасывает очередь записи, затем вызывает completion. Бэкенд объединяет оставшиеся подходящие блоки и публикует версию в outbox. |
| Есть опубликованная версия в outbox и доступен сервер              | Существующий sync worker передаёт недостающие блоки, затем операцию публикации. Неизменённые блоки повторно не отправляются.                                         |
| Процесс был прерван                                                | Уже подтверждённые жесты остаются в SQLite. При следующем запуске сессия допаковывается и публикуется.                                                               |
| Штатное завершение приложения                                      | Нативный exit hook завершает полученные сессии, затем даёт сети до трёх секунд; при отсутствии связи outbox остаётся для следующего запуска.                         |

Дополнительного пятисекундного таймера нет. Минутный таймер — не autosave и не sync.
Общие метаданные заметки, например создание и переименование, используют прежний
механизм синхронизации и могут передаться раньше рисунка.

Проход компакции: до 512 свежих блоков, 8 MiB сжатого входа, 16 MiB декодированных
колонок, целевые блоки до 250 000 точек. Запечатанные блоки не перепаковываются при
следующих обычных правках. Одиночный блок не обязан объединяться с чем-либо.
При восстановлении архива графы отдельно валидируются и пакуются до транзакции
публикации. Объединение сохраняет логические штрихи и гранулярность Undo.

## Контракт команд

Источник истины — `src/lib/bindings.ts`, генерируется `vp run bindings:generate`.
Вручную bindings не редактировать. Все перечисленные команды, кроме
`setHandwritingBackground`, нужно обернуть существующим `checkedCommand` в
`src/lib/api.ts`: сгенерированные функции возвращают typed result, а не сразу value.

| Команда                      | Аргументы                                           | Результат и назначение                                                                                                          |
| ---------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `createHandwrittenNote`      | `title: string \| null`                             | `Page`, обычная новая рукописная заметка                                                                                        |
| `loadHandwritingNote`        | `pageUuid, editing: boolean`                        | `InkHistorySnapshot`: исходный рисунок, revision, canUndo/canRedo. Для ввода обязательно `editing=true`, для просмотра `false`. |
| `saveHandwritingPatch`       | `pageUuid, patch, expectedRevision`                 | Новая revision. `null` допустим только для ещё пустого корня, это не force-overwrite.                                           |
| `handwritingHistory`         | `pageUuid, redo: boolean, expectedRevision`         | `InkHistoryUpdate`; `false` — Undo, `true` — Redo. Для первоначального чтения отдельная load-команда.                           |
| `completeHandwritingNote`    | `pageUuid`                                          | `InkNoteStatus` после упаковки и публикации; не означает, что сервер уже подтвердил получение.                                  |
| `completeAllHandwriting`     | нет                                                 | Завершает известные изменённые/открытые сессии; до вызова сбросить все JS-очереди.                                              |
| `setHandwritingBackground`   | `background: boolean`                               | Сообщает о visibility; при `true` запускает completion. Поздние сохранения в фоне также вызывают completion.                    |
| `handwritingNoteStatus`      | `pageUuid`                                          | Рабочая revision, unpublishedChanges, publicationRequested, baseVersion и heads                                                 |
| `previewHandwritingVersion`  | `pageUuid, versionUuid`                             | `InkDraft` выбранной опубликованной ветки для отрисовки сравнения                                                               |
| `resolveHandwritingConflict` | `pageUuid, expectedHeads: string[], keep: string[]` | UUID сохранённых заметок: первая — исходная, остальные — новые копии                                                            |

`InkDraftPatch` содержит полный `order` видимых UUID штрихов, `upserts` только
добавленных/изменённых штрихов, `background: "plain" | "grid"`. Удаление — отсутствие
UUID в `order`. Не пересылать заново геометрию неизменившихся штрихов.
`incrementalDraftSaver` уже реализует такой diff по ссылочной идентичности объектов;
ему достаточно передать замыкание с UUID текущей заметки.

`applyHistoryUpdate` уже умеет применять дельту и проверяет её `baseRevision`.
Перед Undo/Redo обязательно `await writer.flush()`, затем применить результат,
обновить writer/revision/canUndo/canRedo и сбросить выделение. При ошибке не терять
неподтверждённые локальные данные и не повторять их с выдуманной новой revision.

## Жизненный цикл редактора — обязательная часть интеграции

1. Дождаться готовности приложения и загрузить `Page`. Роутинг по `page.kind.kind`,
   а не по layout. Для рукописи не монтировать текстовый редактор и не создавать блок.
2. Получить `loadHandwritingNote(uuid, true)`, создать отдельный writer для этого UUID.
   Не переиспользовать один singleton writer при переключении между заметками.
3. Сохранять завершённые жесты через очередь, обновляя acknowledged revision только
   после успешной команды. Это касается Pen SDK, Web Pointer Events и мыши одинаково.
4. На Back сначала закончить текущий нативный жест и дождаться flush. После надёжной
   локальной записи навигация может закрыться, но promise completion должен оставаться
   управляемым вне уничтоженного компонента. Ошибку показать как повторяемую ошибку
   сохранения/подготовки синхронизации; не считать уход со страницы подтверждением сервера.
5. На visibility hidden/pagehide: завершить жест, передать background=true, flush,
   complete. Android Suspended уже вызывает native completion, но не умеет извлечь
   точки, ещё оставшиеся только в JS или нативном незавершённом жесте.
6. На visible/resume: background=false, дождаться предыдущего completion для этой
   заметки и снова открыть редактор с `editing=true` перед новым вводом. То же при
   быстром повторном открытии. Не допускать, чтобы старый completion закрыл новую сессию.
7. На штатное закрытие окна сначала сбросить frontend/native очереди. Нативный exit
   hook страхует уже доставленные данные, но не гарантирует доставку данных из
   уничтоженной WebView или callback при принудительном убийстве процесса.

Признак `editing` фиксируется вместе с первоначальным чтением. Пока он установлен,
приход удалённой версии не подменяет холст под пером, даже до первого локального
штриха. Если локальных правок нет, completion может принять единственную удалённую
ветку. Поэтому после completion/resume нужно перечитать состояние, а не продолжать
работу со старой revision. Два параллельных редактора одного UUID не поддерживаются
как совместная сессия: CAS защитит данные, но интерфейс должен обработать конфликт.

`DomainEvent::PagesChanged` отправляется после публикации/разрешения конфликтов,
обычные события sync тоже остаются. Инвалидировать списки и статус; не заменять
активный рисунок на каждом событии без учёта жеста, pending writes и revision.

## Конфликты

`heads.length > 1` означает конфликт опубликованных версий. `heads` содержит
`versionUuid`, `deviceName`, `deviceId`, `modifiedAtMs` (epoch milliseconds),
`rootHash`, `parents`, `available`. Даты в `Page` имеют прежние единицы — не путать.

Для сравнения отрисовать `previewHandwritingVersion` рядом для каждой головы,
подписать устройством и датой. Если `available=false`, версия ещё не загружена;
нельзя превращать ошибку чтения в пустой рисунок и сохранять его поверх заметки.
Начальное чтение тоже может отклоняться, если есть только метаданные без тела.

Перед разрешением закончить локальные правки, вызвать completion, перечитать heads.
Передать ВСЕ текущие UUID в `expectedHeads`, в `keep` — выбранные в нужном порядке.
Одна выбранная версия остаётся в исходной заметке. При нескольких вариантах первая
остаётся, остальные становятся обычными отдельными заметками с суффиксом устройства.
При stale/conflict ошибке перечитать варианты и снова показать выбор. Кнопка «Позже»
не вызывает resolve. Веток бывает больше двух; UI не должен жёстко предполагать пару.

## Фронтенд: конкретный оставшийся объём

- Заменить старые экспорты `loadHandwritingDraft`, `saveHandwritingDraft`,
  `compactHandwritingDraft` в `src/lib/api.ts` на новые команды.
- Переделать `handwriting-session`/маршрут с boolean открытого scratch-диалога на UUID
  заметки; подключить создание и открытие из общего списка. `HandwritingSheet` ещё
  вызывает старые сигнатуры load/save/history/completion и намеренно не обновлён.
- Переиспользовать `DraftWriter`, `ink-patch`, `complete-draft`, холст, инструменты,
  Pen SDK и логику E-Ink. Переименовать helpers при необходимости; singleton-хранилище
  обратно не добавлять. Правки интерфейса не должны ломать frame fence и eraser gate.
- Организовать большую рабочую область, Back вместо Done, убрать постоянные надписи
  о числе штрихов, input details и saved on device. Ошибки должны оставаться видимыми.
- Добавить просмотр, создание с учётом capabilities, сравнение конфликтов и выбор веток.
  Capability ограничивает предложение создать/рисовать, а не доступ к существующей
  заметке. На desktop `stylus=unknown`; доступны наблюдение PointerEvent pen и ручное
  разрешение. Android `not_detected` — текущее наблюдение, не вечный запрет.
- На обычных устройствах остаётся HTML canvas/Pointer Events; Onyx Pen SDK — только
  ускорение захвата/вывода. Формат, история, заметки и sync не привязаны к Onyx.
- После интеграции проверить экранный жизненный цикл на BOOX, desktop и двух клиентах.

## Границы готовности и оставшиеся ограничения

- Серверные изменения не развёрнуты на пользовательском сервере. Нужно обновить
  сервер и оба клиента одной совместимой сборкой. Sync format v7 читает старые v6
  текстовые операции; старый сервер/клиент не получает поддержку рукописи автоматически.
- На книгу новая сборка не установлена. Нельзя считать этот этап аппаратной проверкой
  интегрированного UI. Перед установкой сохранить копию существующей `notes.db` и
  проверить миграцию этой копии; старую тестовую базу не импортировать.
- В текущем адаптере одна страница 1000×1400, до 150 000 точек. Пагинация, бесконечный
  холст, многостраничная заметка, OCR/VLM, поиск по распознанному тексту, формулы и
  редактируемые распознанные объекты ещё не реализованы. Не обещать их кнопками UI.
- JSON остаётся IPC для штрихов/дельт и первоначальной полной загрузки. Arrow/бинарный
  IPC в этом этапе не добавлялся. Хранилище и передача геометрии по сети бинарные.
- Уже опубликованные версии пока сохраняются без политики удаления исторических
  тел. Full snapshot загружает графы всех известных опубликованных версий, а не
  только последних heads; повторные блоки дедуплицируются. Это рабочая, но ещё не
  оптимальная политика долгой истории/первой синхронизации. Локальная Undo-история
  отдельно не синхронизируется, однако опубликованный блок может содержать сегменты,
  удержанные упаковкой локальной истории.
- Неисправная публикация откладывается до попадания в outbox, не блокируя текстовые
  правки. Но ошибка загрузки уже опубликованного графа останавливает содержащую его
  sync-пачку до повтора: изоляция постоянной ошибки отдельного объекта — будущая работа.
- Workspace archive временно держит сжатые ink blobs в памяти: предел 128 MiB уникальных
  рукописных данных, 256 MiB суммарных графов с пересечениями. Большие архивы требуют
  потокового адаптера. Это явная ошибка, не молчаливый пропуск рисунков.
- Имя и формат отдельного переносимого файла одной заметки по-прежнему отложены.

## Проверки и воспроизведение

Итоговый прогон шести Rust-пакетов: **256 passed, 0 failed, 1 ignored**.
Пропущен существующий тест импорта личного каталога Logseq, не относящийся к рукописи.
Отдельно прошли desktop cargo check и Android ARM64 cargo check. Frontend: **402 passed**;
проверка типов ожидает описанную выше адаптацию UI.

Основной автоматизированный сквозной сценарий: `server/tests/ink_sync.rs` поднимает
реальный HTTP/WebSocket-сервер на временном локальном порту и два клиента с отдельными
SQLite. Проверяет обмен, ноль новых блоков при повторной отправке, офлайн-ветки,
сохранение обеих, загрузку новым клиентом, чужие блоки и неполную публикацию.

`crates/notes-core/tests/handwriting_storage.rs`: независимые документы, compaction/GC,
постоянная история, stale revision, откат транзакций, causal conflicts, активный редактор
при remote arrival, сохранение рукописи в архиве и откат восстановления. Scheduler tests
используют управляемое время и инъекцию сбоя публикации. Portable archive test в Tauri
проверяет именно бинарный контейнер и восстановление в SQLite.

```sh
cargo test -p ink-format -p notes-core -p notes-protocol -p notes-sync -p notes-server -p tangleaf
cargo check -p tangleaf -p ink-storage-bench
vp run bindings:generate
vp check
vp test
```

До UI-интеграции `vp check` ожидаемо сообщает шесть ошибок старых команд/сигнатур в
`src/lib/api.ts` и `src/features/handwriting/handwriting-sheet.tsx`. Не скрывать их cast
или compatibility-заглушками. Существующие 402 frontend-теста проходят, но не покрывают
ещё не созданный интегрированный экран. Android Rust check выполняется с NDK clang
для `aarch64-linux-android`; это проверка компиляции Rust, а не сборка APK и не тест пера.

После UI-интеграции: создать две рукописные и одну текстовую заметку; писать и стирать,
Undo/Redo после перезапуска; Back и фон; офлайн завершение и повторный запуск; увидеть
запись на другом устройстве; конфликт обеих офлайн-копий и keep-one/keep-both;
удаление с резервной копией и восстановление; смена DPI/ориентации; отсутствие
скачков лассо, пропавших штрихов и возврата стёртого текста на физическом E-Ink.
